# Azeroth Survivors Trainer

《艾泽拉斯幸存者》Windows 修改器，提供 **36 项对局／天赋功能**，以及全职业收藏、宝箱装备图鉴和成就的永久解锁。当前功能版本为 **v3.3.1**，界面为简体中文。

GitHub 仓库：[Ffive55/azeroth-survivors-trainer](https://github.com/Ffive55/azeroth-survivors-trainer)。

下载当前版本：[v3.3.1 Windows x64 发行包](https://github.com/Ffive55/azeroth-survivors-trainer/releases/download/v3.3.1/azeroth-survivors-trainer-v3.3.1-windows-x64.zip)，或查看 [Release 说明与校验文件](https://github.com/Ffive55/azeroth-survivors-trainer/releases/tag/v3.3.1)。

这是独立的社区工具。仓库只收录修改器源码、生成的补丁模板、测试和文档；游戏需自行安装。

## 支持版本与运行环境

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows x64 |
| 游戏 | Azeroth Survivors `0.119.0 (77b20bb3)` |
| 游戏 EXE SHA256 | `6cb443c6ee7bd8c6e08ea9fd22f715f21ef4bd9aab4f58caff83371fdb9e198f` |
| 运行打包后的 EXE | 无需安装 Python、Cheat Engine 或汇编器 |
| 从源码运行／构建 | 本次验证使用 Python 3.12 x64，需包含 Tkinter |

程序会核对游戏路径、完整 SHA256、进程身份和补丁指令。其他游戏版本需要重新适配；校验失败时会停止连接或写入。

## 安装与启动

将**整个修改器文件夹直接放在游戏 EXE 所在目录下**。文件夹可以使用仓库名，程序按上一级目录寻找游戏：

```text
AzerothSurvivors/
├─ AzerothSurvivors.exe
├─ Data/
├─ benilla-config/
└─ azeroth-survivors-trainer/
   ├─ AzerothTrainer.exe       # 在本机构建后生成，Git 不收录
   ├─ README.md
   ├─ app.py                  # 从源码运行的入口
   └─ ...
```

1. 启动游戏，只保留一个游戏实例。
2. 双击本机构建的 `AzerothTrainer.exe`，或按下文从源码启动。
3. 确认窗口显示 **v3.3.1**，等待自动连接；也可以点击左侧“连接游戏”。
4. 点击“备份并启用全部”，或直接应用所需功能，首次安装相应补丁前会自动备份。该按钮安装对局／天赋支持，不会执行永久解锁。
5. 进入战斗、抽卡或暂停阶段后设置对局数值；天赋在游戏天赋页操作，永久解锁有独立窗口。

界面没有全局热键。列表支持滚轮滚动，点击每行的 `ⓘ` 可查看说明和范围。

**从旧目录迁移时：**先停止保持、恢复需要恢复的天赋预算并撤销旧补丁，再关闭旧修改器。推荐正常退出并重启游戏后使用新目录。新目录不会继承旧目录的 `sessions/`；仅关闭旧修改器窗口可能仍留下天赋或读取挂接，同一游戏进程中换目录可能被识别为未知补丁。

## 输入、应用与保持

输入框是准备应用的目标值，“当前”显示读回的数值。百分数直接输入百分数，例如暴击率 `80` 表示 `80%`；倍率输入 `3` 表示 `3×`。

- **普通数值：**输入后点击“应用”写入一次，开启左侧开关可保持。关闭保持会停止覆盖，已经写入的数值继续由游戏使用。
- **原生持续覆盖：**幸运、生命偷取、荆棘反伤、对受控敌人伤害、两类候选卡数量和游戏速度，点击“应用”后即持续生效；关闭该行开关可停止。停止属性覆盖不会把已经写入的属性恢复成旧值，游戏可能在下一次属性重算时更新它。
- **无敌／一击必杀：**点击“启用”或开关开启，再次点击关闭。
- **天赋：**输入的是“剩余可用点数”，不提供冻结开关，操作方式见专节。

### 战斗开关与变速（3 项）

| 功能 | 输入范围 | 如何使用与实际效果 |
| --- | --- | --- |
| 无敌：受击不掉血 | 开／关 | 点击“启用”，在玩家受伤入口阻止扣血和扣盾；关闭后恢复原生受伤流程。 |
| 一击必杀 | 开／关 | 启用后在实际命中敌人时放大伤害；需要攻击到敌人，游戏的特殊阶段或免疫规则仍可能影响结果。 |
| 游戏速度 | `0.1–10×` | 输入倍率并应用；滑条可选 `0.1–5×`，更高倍率手动输入。计时、移动、技能和敌人模拟同步变速，音频和窗口动画保持原速；关闭开关回到 `1×`。 |

## 天赋点数的完整用法

1. 在游戏中进入军械库的天赋页，选择要修改的职业。
2. 在修改器左侧“天赋职业”选择相同职业，点击“备份并启用全部”，或直接应用“可用天赋点数”。
3. 如果提示尚未读取职业，在游戏中切换到其他标签，再回到天赋页，然后重试。
4. 输入希望**剩余可用**的点数并应用；切换游戏标签刷新显示，再正常学习天赋。

例如已经投入 `19` 点，输入 `50` 后，总预算是 `69`、可用点数是 `50`。点数会随着学习自然扣减；单项天赋等级和前置要求继续生效。

支持战士、圣骑士、猎人、潜行者、牧师、萨满、法师、术士和德鲁伊。降低预算或恢复原生预算时，会检查所有三套方案；其他方案投入更多点数时会拒绝降低。

“恢复与说明”中的“恢复所选职业的原生天赋”会按原有天赋经验恢复预算。超额分配时须先在游戏里退回多余天赋，再恢复或撤销补丁。

**天赋预算仅作用于当前游戏进程，不保证超额分配跨游戏重启保留。**游戏自身保存的天赋在没有预算补丁时可能被原生规则清理。永久解锁功能不会把天赋预算变成永久功能。

## 永久解锁：收藏、图鉴与成就

保持游戏运行，建议在主菜单操作，点击左侧“永久解锁 · 收藏 / 图鉴 / 成就”。窗口会读取游戏驱动真正持有的进度；也可点击“刷新当前永久进度”。

| 按钮 | 如何使用 | 范围与结果 |
| --- | --- | --- |
| 收藏装备 + 同步掉落表 | 选择一个职业或“全部职业”，点击按钮 | 补齐所选职业收藏，并同步开放其 `12` 个区域的掉落表；9 职业共 `498` 件，潜行者／萨满各 `60` 件，其余各 `54` 件。 |
| 宝箱装备图鉴（传说品质） | 选择一个职业或“全部职业”，点击按钮 | 补齐 `39` 件共用珠宝及目标职业专属传说项链的发现记录，品质设为传说。9 职业专属项链合计 `103` 件。 |
| 全部成就 + 同步成就点数 | 直接点击，职业选择不影响此操作 | 解锁账号共享的 `98` 项成就，包括职业及合作成就，目录总计 `2,270` 点；保留已有成就时间和奖励消费记录。 |
| 全部职业一键解锁以上项目 | 直接点击，始终覆盖全部职业 | 一次完成全部职业收藏、掉落区域、宝箱图鉴和全部成就。 |

等待显示“已即时解锁并保存”，再切换游戏收藏、掉落表、图鉴或成就标签刷新显示。无需退出游戏执行解锁，保存后的结果可在正常退出和重开后保留。

重复解锁不会重复增加成就点数。`2,270` 是目录总点数，可用余额仍要扣除已经消费的奖励点数。解锁保持现有穿戴、外观、天赋和统计记录。

v3.3.1 修复了旧版修改界面副本、被游戏后续保存覆盖的问题。此前已被覆盖的解锁需要用新版重新执行。实现细节见 [AGENTS.md](AGENTS.md)，版本变化见 [更新记录](docs/CHANGELOG.md)。

## 停止、还原与备份恢复

| 操作 | 行为 |
| --- | --- |
| 关闭单行开关 | 停止该项保持或原生覆盖；游戏速度恢复 `1×`，已经写入的普通属性不自动恢复旧值。 |
| 还原本次窗口设置 | 关闭高级覆盖，恢复本窗口首次修改前记录的普通数值；也可能撤销此后自然发生的数值变化。此操作不恢复天赋或永久解锁。 |
| 恢复所选职业的原生天赋 | 按原有天赋经验恢复预算，执行前需保证所有方案没有超额投入。 |
| 停止保持并撤销全部运行时补丁 | 停止保持并恢复入口原指令；若天赋仍超额，会被保护性拒绝。已保存的永久解锁继续保留。 |
| 关闭修改器窗口 | 停止保持、无敌、一击必杀及高级覆盖，速度恢复原速，撤销永久解锁驱动挂接。天赋和对局读取挂接可能保留到游戏退出。 |
| 正常退出游戏 | 游戏进程内的运行时补丁随进程释放；游戏自己的存档按原生流程保存。 |

备份和运行状态位于修改器目录内：

- `backups/<时间>/`：启用相关运行时补丁前的游戏 EXE、默认 `%APPDATA%/wenilla-rogue/` 存档、游戏配置及 SHA256 清单。启用不同模块可能分别创建备份。
- `backups/unlocks-<时间>/`：永久解锁前的真实内存进度 `characters.txt`、磁盘原始存档 `disk-before.txt`、操作清单 `manifest.json` 和成功结果 `result.json`。其中内存快照使用原生 `RSE1` 封装，并经游戏解码验证。
- `sessions/`：当前进程的补丁重连信息，按 PID 与创建时间区分；游戏仍运行时不要删除或移动。
- `logs/events.jsonl`：操作日志。

默认存档为 `%APPDATA%/wenilla-rogue/characters.txt`。永久解锁会读取游戏实际使用的路径，也支持游戏通过 `WOW_ROGUE_SAVE` 指定的路径；普通完整备份和 CLI 恢复仍使用默认 `%APPDATA%` 目录。

**恢复存档必须先退出游戏。**先另存当前存档，再恢复所选备份；恢复会把整份进度退回备份时刻。永久解锁备份中的实际路径和哈希见 `manifest.json`。普通备份可用下面的 CLI 恢复；`unlocks-*` 备份结构不同，不能传给该 CLI 命令，应按其清单手动恢复。

## 从源码运行、测试与构建

在本仓库根目录打开 PowerShell。源码直接运行只使用 Python 标准库；安装开发依赖后可以运行全部测试、二进制分析和构建工具。

```powershell
# 创建本机开发环境（Python 3.12 x64）
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt

# 启动界面
.\.venv\Scripts\python.exe app.py

# 回归测试；最后一组只读取相邻游戏 EXE，不连接游戏进程
.\.venv\Scripts\python.exe -m unittest discover -s . -p "test_*.py" -v

# 打包到本仓库根目录，保持上述相邻游戏路径关系
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --distpath . --workpath build AzerothTrainer.spec
```

如只需要不依赖游戏安装的内存夹具测试，可执行：

```powershell
.\.venv\Scripts\python.exe -m unittest test_trainer test_runtime_features test_native_v3 test_progression -v
```

这些测试使用模拟内存，不修改游戏进程或个人存档。未安装相邻游戏时，`test_build_compatibility` 会明确跳过；存在游戏文件但版本不符时会失败。自动测试不能替代真实战斗、长时间运行和正常退出后重载的验证。

仓库已包含生成后的 `native_templates_v3.py` 和 `progression_template.py`，直接运行和打包无需重新汇编。修改原生补丁时再生成：

```powershell
.\.venv\Scripts\python.exe build_native_v3.py
.\.venv\Scripts\python.exe build_progression_native.py
```

前一个生成器会校验相邻游戏的完整 SHA256；生成器使用 Keystone，PE 检查使用 Capstone／pefile，PyInstaller 用于打包，固定依赖见 `requirements-dev.txt`。

### 命令行：天赋诊断与恢复

`cli.py` 只提供天赋及普通备份恢复接口，对局属性和永久解锁通过图形界面操作。

```powershell
.\.venv\Scripts\python.exe cli.py status
.\.venv\Scripts\python.exe cli.py enable
# 启用后需在游戏内打开对应职业天赋页，以便捕获记录；8 为法师
.\.venv\Scripts\python.exe cli.py set --class-id 8 --value 50
.\.venv\Scripts\python.exe cli.py restore --class-id 8
.\.venv\Scripts\python.exe cli.py disable
# 游戏必须已退出；此处填写真实普通备份目录
.\.venv\Scripts\python.exe cli.py restore-save --backup ".\backups\<时间>"
```

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 游戏路径不匹配 | 确保修改器文件夹直接位于游戏目录下，上一级有 `AzerothSurvivors.exe`；不要把 EXE 单独移到桌面。 |
| 游戏版本不匹配 | 对照上面的完整 SHA256。升级游戏后需要重新适配，不能跳过校验继续写入。 |
| 检测到未知内存补丁 | 停用其他修改器；若刚从旧目录迁移，按迁移步骤正常退出并重启游戏，再连接。 |
| 找不到存档，停止修改 | 先在游戏中正常创建并保存进度。普通模块要求默认存档存在；自定义测试存档的差异见备份章节。 |
| 当前值是 `—`／对局读取未启用 | 应用功能或启用对局支持后进入有效对局；生命偷取和候选数量在未覆盖／非对应手牌阶段也可能显示 `—`。 |
| 天赋职业尚未读取 | 启用天赋支持，在游戏中打开相应职业天赋页并切换一次标签。 |
| 调整卡数量后当前手牌没变 | 正常现象，从下一次对应发牌或重抽生效，候选池也可能不足目标数量。 |
| 永久进度在准备期间变化／提交被拒绝 | 等待当前操作完成，刷新永久进度后重试；不要在提示仍执行时重复提交。 |
| 撤销补丁提示天赋超额 | 检查所有职业的全部三套方案，退回原生预算以内，再恢复或撤销。 |

## 项目结构与 GitHub 准备

| 文件／目录 | 用途 |
| --- | --- |
| `app.py`、`app_v2.py` | 启动入口与当前 v3.3.1 界面，模块名沿用历史命名。 |
| `engine.py`、`winmem.py`、`talents.py` | 连接、身份校验、备份、进程内存访问和天赋规则。 |

| `build_*.py`、`*_template*.py`、`AzerothTrainer.spec` | 原生模板生成器、生成结果和 EXE 打包入口。 |
| `test_*.py` | 模拟内存回归与只读版本兼容检查。 |
| `AGENTS.md` | 各功能的实现路径、字段、挂接、约束及维护工作流。 |
